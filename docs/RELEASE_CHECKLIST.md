# قائمة فحص الإصدار

## سلامة الملفات
- [ ] فك ZIP إلى مجلد جديد والتأكد من عدم وجود ملفات خارج المشروع لازمة للتشغيل.
- [ ] التأكد من وجود الملفات التوثيقية الأساسية والمصفوفات.
- [ ] فحص الأسرار ومفاتيح API والبيانات الشخصية قبل الرفع.
- [ ] إذا توفرت ملفات `originals/` خارج الحزمة، تحقق من حفظها كمرجع وعدم تعديلها دون قرار صريح؛ هذا ZIP لا يتضمن ذلك المجلد، فلا تدّعِ مطابقة بصرية قبل توافره.

## تشغيل واختبار محلي
- [ ] تثبيت إصدار Node مدعوم.
- [ ] تشغيل `npm test`.
- [ ] تشغيل خادم HTTP محلي.
- [ ] فتح العميل والمدير على الأصل نفسه.
- [ ] تنفيذ مسار قبول يدوي من التسجيل إلى طلب النقاط ثم الاعتماد ثم الرقم والاشتراك والمهمة والمالية.
- [ ] تجربة عرض RTL وحالات الفراغ والخطأ والنوافذ الطويلة على هاتف فعلي.

## قواعد وبيانات
- [ ] اعتماد البادئات وأطوال الأرقام من مصدر صحيح ومؤرخ.
- [ ] اعتماد التعرفات والمدد وباقات النقاط ووسائل الدفع ومصروف المهمة.
- [ ] توثيق قرار صفة «المشترك» ووقت الاعتراف بالإيراد.
- [ ] مراجعة اللقطات التاريخية ومنع التكرار والعلاقات.
- [ ] اعتماد معالجة القيود المالية الخاطئة بالعكس بدل الحذف.

## قبل الإنتاج
- [ ] نشر SQL في staging بعد مراجعة مستقلة.
- [ ] تفعيل Auth وRLS وRPC والتحقق من كل الأدوار.
- [ ] اختبار التزامن والتراجع والنسخ الاحتياطي والاستعادة.
- [ ] إكمال ربط Android/Supabase إن كان ضمن الإصدار.
- [ ] تحديد مزود الدفع/الإشعارات/الاتصال الخارجي، إن تقرر استخدامها.
- [ ] اجتياز اختبار أمني وقبول نهائي موثق.

## رفع GitHub
- [ ] تحقق من `git status` والفرع الهدف.
- [ ] لا تضمّن `.env` أو كلمات مرور أو مفاتيح.
- [ ] راجع الفرق كاملًا قبل commit.
- [ ] أنشئ commit برسالة تصف الاستكمال.
- [ ] ادفع إلى المستودع فقط بعد مراجعة التغييرات والنسخة الاحتياطية.
