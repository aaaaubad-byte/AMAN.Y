# خطة تنفيذ المعاينة المحلية (البنود 1–112)

المرجع الحاكم: التوجيه النهائي لصاحب المشروع + `DECISIONS_112.md`. تتبّع الحالة: `ITEMS_TRACKER.md`. السجل: `PROGRESS_LOG.md`.

## الحدود الثابتة
- المعاينة المحلية فقط. لا Supabase، لا قاعدة بيانات أو جداول أو سياسات وصول أو خدمات خلفية، لا نشر، ولا تجهيز ضمني لأي منها.
- تطبيقا العميل والإدارة منفصلان (`apps/customer*` و`apps/admin*`). لا يستورد أحدهما من الآخر. المشترك فقط ما في `shared/`.
- منطق العمل والتخزين المحلي (`AMAN_SHARED_REGISTRY_V2`) يبقيان. أي حقل جديد يُضاف **إضافيًا وبقيمة افتراضية** داخل `normalize()` بحيث تُقرأ البيانات القديمة بلا فقد، ويُوثَّق في هذا الملف وفي سجل التقدم.
- لا بيانات وهمية ولا شاشات تجريبية في النسخة الأساسية (البند 110). المخزن الابتدائي فارغ.
- لا تُنفَّذ البنود المرفوضة (7، 88، 90، 91، 95، 101، 104) ولا المؤجلة (9، 20، 70، 108)، ولا يُبنى لها هيكل أو واجهة.
- لا قرارات تجارية جديدة نيابة عن المالك: أي قيمة أو قاعدة غير محسومة تُسجَّل في «أسئلة مفتوحة» بسجل التقدم، وتُنفَّذ كإعداد إداري قابل للتغيير بلا قيمة تجارية مختلَقة قدر الإمكان، أو يُترك البند إلى حين الحسم.
- لا تُرسل أي تغييرات إلى `main` ولا يُدمج الفرع قبل التحقق وموافقة المالك الصريحة.

## سياسة الفحص (البند 112)
- لا إضافة أي workflow/CI يشغّل اختبارات عند كل دفع.
- نقطة تحقق الوحدة: `npm test` (يستغرق أقل من ثانية) + فحص ثابت لما لُمس. لا اختبار متصفح مكلف بين الوحدات.
- اختبار المتصفح الكامل (Playwright) مرة عند نهاية كل مرحلة كبرى ومرة قبل التسليم، إن توفرت الأداة، وإلا يُذكر صراحةً أنه لم يُنفَّذ.
- لا يُدَّعى نجاح فحص لم يُنفَّذ؛ يُفرَّق بين «يُبنى» و«يعمل» و«اختُبر في متصفح».

## قاعدة كل وحدة
فحص الوضع الحالي → تعديل أصغر ما يلزم → اختبار مصاحب لمنطق البيانات الجديد → `npm test` → commit واضح → push إلى `feature/local-preview-112` والتحقق بـ `git ls-remote` → تحديث `ITEMS_TRACKER.md` و`PROGRESS_LOG.md` (في نفس الـ commit أو التالي مباشرة). لا انتقال لوحدة جديدة والوحدة الحالية غير مستقرة.
