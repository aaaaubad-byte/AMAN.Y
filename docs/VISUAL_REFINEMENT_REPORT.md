# AMAN | أمان — تقرير المراجعة البصرية والوظيفية

## نطاق العمل

- المرجع البصري: `originals/CUSTOMER.html` و`originals/ADMIN.html` المحفوظان كما وردا داخل الحزمة.
- مصدر الوظائف: `apps/customer.js` و`apps/admin.js` و`shared/data.js`.
- هذه نسخة HTML محلية تفاعلية، وليست تطبيق Android أو نظام إنتاج متصلًا بـ Supabase أو ببوابة دفع.

## ما تم إصلاحه

1. إعادة تثبيت الأزرار الأساسية والرصيد والتنقل النشط على الأسود/الفحمي (`#141615`) بدل الطبقة الخضراء/الفيروزية التي خالفت المرجع.
2. نقل زر الإجراء العائم في الإدارة إلى `#floatingRoot` خارج عنصر المحتوى القابل للتمرير. اختُبر ثبات موضعه قبل تمرير المحتوى وبعده في Chromium.
3. استخدام أيقونات SVG خطية لأيقونة الصفحة الرئيسية، الحساب، الإعدادات (منزلقات لا ترس)، الأمان، المساعدة، المستند، النسخ، الإغلاق، السهم والإضافة؛ وإزالة رموز Unicode العشوائية من هذه المواضع.
4. توحيد شكل النافذة المنبثقة بحيث يبقى رأسها وأزرارها في مساحة واضحة، ويكون المحتوى الطويل قابلًا للتمرير داخل النافذة.
5. منع حفظ نماذج الإدارة غير المكتملة عبر `reportValidity()` قبل إجراء الحفظ.
6. إضافة إغلاق النافذة بمفتاح Escape والتركيز على زر الإغلاق عند فتحها.
7. إزالة النصوص التجريبية الخاصة بإعادة التهيئة من شاشات تسجيل الدخول، وإبقاء إعادة التهيئة اليدوية في الحساب الإداري ووثائق التشغيل.
8. إزالة النصوص/العناصر الفارغة، وإضافة حالات فارغة واضحة للشركات وباقات النقاط ووسائل الدفع والسجل المالي، وحالات عدم توافر الباقات/وسائل الدفع.
9. إزالة اعتماد خطوط Google الخارجية واستخدام خطوط النظام حتى تعمل الواجهة دون طلبات شبكية إضافية؛ لا توجد مكتبات JavaScript خارجية مطلوبة.
10. تصحيح بيانات الاختبار حتى تتوافق صفة «مشترك» مع وجود طلب نقاط معتمد، واحتساب خصم الاشتراك المنتهي ضمن دفتر النقاط.
11. توسيع بيانات الشركات التجريبية لتغطي البادئات 77/78 و73 و71 و70. التعرفات والمبالغ التشغيلية لا تزال قيم اختبار وليست أسعارًا تجارية معتمدة.
12. ضبط اتجاه عرض البريد والمعرّفات اللاتينية داخل الواجهات العربية.

## جرد الواجهات

### العميل

- حالات الدخول: تسجيل الدخول، إنشاء حساب.
- المسارات: الرئيسية، الأرقام، تفاصيل الرقم (نافذة)، الرادار، شراء نقاط، العمليات، الإشعارات، الحساب، الإعدادات، تأمين التطبيق.
- نوافذ إضافية: تفاصيل عملية، إشعارات الرقم، تفاصيل إشعار، المساعدة، الشروط، الخصوصية، تأكيد تسجيل الخروج.

### الإدارة

- تسجيل الدخول.
- المسارات: الرئيسية، المشتركون، كل العملاء، المهام المستحقة، كل المهام، طلبات النقاط المعلقة، كل طلبات النقاط، الاشتراكات الفعالة، كل الأرقام، السجل المالي، الشركات، باقات النقاط، وسائل الدفع، الإشعارات، المدخلات، البحث الشامل، الحساب الإداري، سجل التدقيق.
- النوافذ والنماذج: تفاصيل العميل، الرقم، طلب النقاط، المهمة؛ إضافة/تعديل شركة أو باقة أو وسيلة دفع؛ إنشاء إشعار محلي؛ إضافة قيد مالي.

## نتائج الاختبارات

- `node --check` لملفات JavaScript الأساسية: ناجح.
- نتيجة الاختبارات الحالية موثقة في `TEST_REPORT.md`؛ جولة الإصلاح الحالية شغلت 34 اختبارًا ونجحت كلها.
- اختبار Chromium تفاعلي عبر تحميل الشيفرة داخل صفحة اختبار مع مخزن تخزين مؤقت: دخول العميل والإدارة، مسارات العميل الرئيسية والفرعية، إضافة رقم واي وطلب نقاط، تفعيل اشتراك والرادار وتفاصيل العمليات والإشعارات وتأكيد الخروج؛ ومسارات الإدارة الثانوية، تفاصيل العميل/المهمة/الطلب، تنفيذ مهمة، رفض واعتماد طلب، إضافة شركة وباقة ووسيلة دفع، إنشاء إشعار، حفظ المحتوى، البحث، القيد المالي، والتحقق من النماذج المطلوبة. لم تظهر أخطاء JavaScript في هذه السيناريوهات. كما اختُبر عدم وجود تمرير أفقي في عروض 280 و320 و360 و390 و430 بكسل.

## ما لم يثبت بعد

- لم يُختبر المشروع من خلال خادم محلي فعلي ومتصفح مستخدم عادي في هذه الجولة؛ اختبار Chromium استخدم مخزنًا مؤقتًا بدل `localStorage` الحقيقي بسبب قيود بيئة التنفيذ.
- لم تُختبر كل تركيبة نقر/حالة/مقاس شاشة لكل نافذة. نتائج الاختبار أعلاه هي مسارات دخان تفاعلية وليست اختبار قبول شاملًا.
- لا يوجد تكامل فعلي مع Supabase أو Android أو المحافظ أو الدفع أو إرسال الإشعارات الخارجية.
- يجب مراجعة التعرفات والباقات والمصروفات وتعليمات الدفع قبل اعتماد أي بيانات تجارية.

## تعديل مساحة البيانات والأزرار العائمة (2026-10-12)

- أُزيلت البيانات الاصطناعية من تهيئة التطبيق الفعلية: العملاء والشركات والباقات ووسائل الدفع والأرقام والاشتراكات والطلبات والمهام والسجلات والإشعارات تبدأ فارغة.
- رُفع مفتاح المخزن إلى `AMAN_SHARED_REGISTRY_V2` لمنع إعادة استخدام السجلات القديمة تلقائيًا.
- أُزيل إجراء إعادة تعبئة البيانات من واجهات التطبيق، وأُزيلت دالة إعادة التهيئة من واجهة API المشتركة.
- أضيفت أيقونات SVG مختلفة للأهداف الإدارية الرئيسية مثل المهام وسجل الطلبات والهاتف والمستخدمين.
- الأزرار العائمة على الشاشات الرئيسية تنقل إلى الوجهة المطلوبة، ولا يظهر الزر نفسه في شاشة الوجهة لتجنب التكرار.
- أزيلت روابط التنقل المتكررة من مؤشرات وبطاقات الصفحة الرئيسية؛ المؤشرات الآن للعرض فقط.
- شاشة كل الأرقام المشتركة تحتوي إجراء إضافة رقم لعميل موجود.
- بيانات الاختبارات فقط موجودة في `tests/fixture-data.js` ولا تستوردها صفحات التطبيق.
