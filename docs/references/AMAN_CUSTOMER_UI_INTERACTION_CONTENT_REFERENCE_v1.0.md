# AMAN | أمان
# المرجع المستقل لواجهات العميل والتفاعل والتنقل والمحتوى
**الإصدار:** 1.0 — تنقيح 2 (توحيد المصطلحات والقرارات مع مرجع الإدارة تنقيح 5) — **النطاق:** تطبيق العميل — **اللغة:** العربية RTL

## 1. الغرض والنطاق

هذا مرجع مستقل يحدد تجربة العميل كاملة: الشاشات، النوافذ، المحتوى، عناصر الواجهة، حالات البيانات، التفاعل، والتنقل. يجب تنفيذه كمنتج مترابط، لا كمجموعة صور أو شاشات شكلية.

يشمل ثماني شاشات: الرئيسية، الأرقام، العمليات، الحماية، الحساب، الإشعارات، تنبيهات الرقم، تقديم بلاغ. ويشمل نماذج تفاصيل الرقم الخمسة، وتفاصيل العملية، ومراجعة العملية، ونتيجة الإرسال، وتأكيد تسجيل الخروج.

لا يشمل واجهات الإدارة أو تعديل قاعدة البيانات أو إنشاء خدمات خلفية أو اعتماد أسعار وباقات غير موثقة.

## 2. مصادر الحقيقة والأولوية

1. القواعد الوظيفية في هذا المرجع تحكم سلوك العميل.
2. الصورة المرجعية التي يرفقها صاحب المشروع تحكم الهوية البصرية.
3. المستودع يُقرأ لفهم المشروع وأسماء البيانات والأصول والمنطق القابل لإعادة الاستخدام فقط.
4. أي منطق قديم يتعارض مع هذا المرجع لا يُعاد استخدامه.
5. لا تستنتج قرارات تجارية من واجهة قديمة ولا تخترع بيانات ناقصة.

**قيد المستودع:** إذا كان المطلوب ملف معاينة HTML، يمنع تعديل المستودع أو أي ملف داخله أو تنفيذ commit/push أو تغيير الفروع. الناتج ملف مستقل خارج المستودع.

## 3. المفاهيم الوظيفية الحاكمة

### 3.1 الرقم والحماية
- الرقم يُدخل بصيغته المحلية متضمنًا بادئة شركة الاتصالات.
- لا تضف +967 أو مفتاح دولة إلى حقل الإدخال.
- لا تستخدم تسمية «رقم هاتف يمني».
- تحديد الشركة والطول والبادئة يكون وفق بيانات الشركات المعتمدة في المشروع، لا وفق قائمة مخترعة.
- **الحماية** هي النموذج العام لعلاقة الرقم بنظام أمان.
- **المصطلحات في مجموعات منفصلة لا تُخلط:**
  - **تصنيف الحساب:** مستخدم، عميل (3.3).
  - **حالة اشتراك الرقم:** غير مشترك، مشترك (نشط)، اشتراك منتهي (غير نشط) ضمن مهلة التنشيط، مصادَر. وهي التي تحدد العملية المتاحة.
  - **حالة الحماية:** محمي، غير نشط، منتهي-مصادر.
  - **أنواع العمليات فقط:** اشتراك، تمديد الاشتراك، تنشيط.
  - **حالات الطلب:** قيد المراجعة، معتمد، مرفوض.
- لا تخلط تصنيف الحساب بحالة اشتراك الرقم أو بحالة الحماية، ولا حالة الحماية بنوع العملية أو بحالة طلب العملية.

### 3.2 معنى الحالات والعمليات
| حالة اشتراك الرقم | حالة الحماية | المعنى | العملية المتاحة |
|---|---|---|---|
| غير مشترك | لا حالة حماية | الرقم ليس في نظام الحماية بالنسبة للعميل الحالي: لا حماية سارية لأي حساب ولا فترة سابقة لهذا العميل | اشتراك |
| مشترك (نشط) لدى العميل نفسه | محمي | توجد حماية سارية تخص حساب العميل الحالي | تمديد الاشتراك |
| محمي لدى عميل آخر | محمي | توجد حماية سارية تخص حسابًا آخر؛ لا تكشف أي بيانات عنه | لا عملية؛ تقديم بلاغ فقط |
| اشتراك منتهي (غير نشط) لدى العميل نفسه | غير نشط | انتهت فترة الحماية السابقة التي تخص العميل الحالي ولم تنتهِ مهلة التنشيط | تنشيط |
| مصادَر لدى العميل نفسه | منتهي-مصادر | انتهت مهلة التنشيط؛ لا يُسمح بالتنشيط | لا شيء |

| العملية | المعنى |
|---|---|
| اشتراك | أول عملية حماية للرقم لدى العميل (من حالة غير مشترك) |
| تمديد الاشتراك | زيادة فترة الحماية ما دامت سارية |
| تنشيط | بدء فترة حماية جديدة بعد انتهاء الحماية السابقة ما دام الرقم ضمن مهلة التنشيط |

بعد نجاح التنشيط يعود الرقم إلى «مشترك (نشط)» / «محمي»، وتصبح العملية التالية «تمديد الاشتراك». انتهاء اشتراك أمان لا يعني مصادرة الرقم لدى شركة الاتصالات؛ ولا تحقق من الشركة.

### 3.3 تصنيف الحساب والطلبات
- **مستخدم:** لم يُعتمد له أي طلب اشتراك حتى الآن.
- **عميل:** اعتُمد له طلب اشتراك لرقم واحد على الأقل، ويظل عميلًا حتى لو انتهت اشتراكات جميع أرقامه.
- إضافة رقم أو البحث عنه لا يجعل الحساب عميلًا.
- لا توجد نقاط أمان أو محفظة نقاط أو شراء نقاط أو أرصدة نقاط.
- لا يوجد تبويب أو قائمة اشتراكات مستقلة؛ الحماية هي علاقة الرقم بأمان، و«الاشتراك» اسم عملية وحالة للرقم فقط.
- إرسال الطلب لا يبدأ الحماية.
- حالات الطلب المعروضة: **قيد المراجعة، معتمد، مرفوض** فقط.
- لا تتحول الحماية إلى «محمي» إلا بعد اعتماد الطلب وتحديث بيانات الحماية.
- «قيد المراجعة» حالة طلب وليست حالة حماية.

### 3.4 التقويم والمنطقة الزمنية
- المدة المتبقية والتواريخ المعروضة تُحسب بالتقويم الميلادي الفعلي وبتوقيت Asia/Aden، لا بتوقيت جهاز المستخدم.
- لا يظهر للعميل أي تاريخ محسوب بمعيار الأشهر الثلاثينية؛ فهو معيار لأمثلة التوضيح الداخلية فقط.

## 4. التنقل العام

### 4.1 شريط التنقل السفلي
ثلاثة عناصر فقط، بترتيب RTL:
1. الأرقام.
2. الرئيسية.
3. العمليات.

الرئيسية هي الوجهة الافتراضية. لا تضف تبويبًا للحماية أو الحساب أو الإشعارات. الوصول إلى الحساب والإشعارات من أيقونتيهما في الشريط العلوي. الحماية تُفتح من تفاصيل الرقم فقط. تنبيهات الرقم تُفتح من تفاصيل رقم يخص العميل. البلاغ يُفتح من نموذج رقم محمي لدى عميل آخر.

### 4.2 خريطة التنقل
```text
الرئيسية
 ├─ بحث عن رقم → نافذة تفاصيل الرقم (أحد النماذج الخمسة)
 │   ├─ اشتراك → الحماية (العملية ممررة تلقائيًا)
 │   ├─ تمديد الاشتراك → الحماية
 │   ├─ تنشيط → الحماية
 │   ├─ التنبيهات → تنبيهات الرقم
 │   └─ تقديم بلاغ → تقديم بلاغ
 ├─ أيقونة الحساب → الحساب
 └─ أيقونة الإشعارات → الإشعارات

الأرقام
 └─ بطاقة رقم → نافذة تفاصيل الرقم (النماذج الخمسة)

العمليات
 └─ بطاقة طلب → تفاصيل العملية

الحماية
 ├─ اختيار الباقة
 ├─ وسيلة الدفع والتعليمات
 ├─ مرجع الدفع
 ├─ مراجعة العملية
 └─ نتيجة الإرسال
```

### 4.3 قواعد الانتقال
- كل انتقال يحتفظ بسياق الرقم والشاشة التي بدأ منها.
- تمرير الرقم والشركة ونوع العملية إلى شاشة الحماية تلقائي.
- لا يختار العميل نوع العملية بحرية.
- الرجوع يعيد المستخدم إلى سياق الرقم السابق.
- البحث من الرئيسية لا يضيف الرقم إلى قائمة العميل.
- فتح بطاقة من شاشة الأرقام يعني أن الرقم مرتبط بالفعل بحساب العميل.
- لا تعرض إجراءً غير مسموح به لحالة الرقم.
- لا تفتح شاشة فارغة بلا حالة تحميل/فراغ/خطأ مفهومة.

## 5. الهوية ونظام التصميم

الصورة المرجعية المرفقة هي المرجع الحاكم للشعار والألوان والخطوط والأيقونات والبطاقات والحقول والأزرار والنوافذ والمسافات. لا تنشئ هوية بديلة.

- واجهة عربية RTL حقيقية في كل المكونات، لا مجرد محاذاة النص.
- Mobile-first ومناسبة لأحجام الهواتف.
- التزم بلوحة المرجع: الكحلي/الأزرق/الفيروزي/الأبيض والرمادي الفاتح بحسب الصورة.
- تباين واضح ونصوص مقروءة.
- ظلال خفيفة عند الحاجة؛ ممنوع الظلال الثقيلة والبطاقات الضخمة.
- تجنب العناوين المبالغ بحجمها والازدحام والكثافة المكتبية.
- لا تستخدم الإيموجي بدل الأيقونات.
- استخدم عائلة أيقونات موحدة.
- الحالة لا تُفهم باللون وحده؛ يجب إظهار نص الحالة.
- استخدم شبكة مسافات موحدة وأحجام ثابتة للحقول والأزرار والبطاقات.
- الأرقام والتواريخ والمبالغ لا تنقلب أو تتداخل بسبب RTL.
- لا تضع نصوصًا طويلة داخل الأزرار.
- لا تجعل العناصر الزخرفية تزاحم المحتوى الوظيفي.

## 6. الشاشة الأولى: الرئيسية

### الهدف
البحث عن رقم والتحقق من حالته في نظام أمان، مع وصول سريع للحساب والإشعارات. البحث لا يضيف الرقم إلى قائمة العميل.

### ترتيب المحتوى
1. شريط علوي: أيقونة الحساب، هوية/شعار أمان، أيقونة الإشعارات، ومؤشر غير مقروء عند وجوده.
2. تحية أو عنوان قصير، دون اختلاق بيانات شخصية.
3. منطقة البحث: عنوان إرشادي، حقل الرقم المحلي، زر «بحث»، وتوضيح مختصر أن الإدخال محلي متضمن بادئة الشركة دون مفتاح دولة.
4. ملخصات حسابية صغيرة فقط إذا كانت البيانات الفعلية متاحة، مثل عدد الأرقام أو الحمايات السارية. لا تعرض أرقامًا تجريبية كأنها حقيقية.
5. محتوى مساعد أو حالة فارغة مناسبة.
6. شريط التنقل السفلي.

### حقل البحث وسلوكه
- يقبل الرقم المحلي وفق طول وبادئة الشركة من البيانات المعتمدة.
- لا يقبل أحرفًا أو رموزًا غير مسموحة.
- لا يضيف +967.
- لا يشترط أن يكون الرقم موجودًا في قائمة العميل.
- عند عدم تحديد الشركة أو عدم صحة الرقم، تظهر رسالة محددة ومفهومة.
- عند البحث يظهر تحميل، ثم تفتح نافذة التفاصيل الصحيحة.
- فشل الاتصال يعرض خطأ وإعادة محاولة.
- لا يضاف الرقم إلى قائمة العميل بمجرد البحث.

### نافذة تفاصيل الرقم بعد البحث من الرئيسية
**إلزامي:** تعرض هذه النافذة بيانات الرقم نفسها التي تعرضها نافذة تفاصيل الرقم من شاشة الأرقام. لا تختصرها إلى عنوان وحالة وزرين. يجب أن يظهر الرقم والشركة والحالة، وجميع تفاصيل الباقة والمدة والتواريخ المتاحة، والمدة المتبقية، أو بيانات الحماية السابقة، بحسب الحالة. في حالة عميل آخر تظهر رسالة الخصوصية فقط دون بياناته. الاختلاف المسموح هو اختلاف الإجراءات بحسب سياق الدخول، لا حذف تفاصيل البيانات.

النماذج:
- **غير مشترك:** الرقم، الشركة، «غير مشترك»، توضيح أن الرقم غير مشمول بحماية حاليًا، وإجراء «اشتراك».
- **مشترك (نشط) لدى العميل نفسه:** الرقم، الشركة، حالة محمي، اسم الباقة، المدة الإجمالية، تاريخ البداية، تاريخ النهاية، المدة المتبقية، وإجراء «تمديد الاشتراك» والتنبيهات إذا كانت معتمدة.
- **محمي لدى عميل آخر:** الرقم، الشركة، حالة محمي، النص «هذا الرقم محمي حاليًا لدى عميل آخر»، توضيح عدم إمكانية الاشتراك حاليًا، وإجراء تقديم بلاغ. يمنع كشف اسم العميل أو باقته أو تواريخه أو معاملاته.
- **اشتراك منتهي (غير نشط) لدى العميل نفسه:** الرقم، الشركة، حالة غير نشط، اسم الباقة السابقة إن توفر، تاريخ البداية السابقة، تاريخ الانتهاء، آخر يوم للتنشيط إن توفر، توضيح انتهاء الحماية، وإجراء «تنشيط» والتنبيهات إذا كانت معتمدة.
- **مصادَر لدى العميل نفسه:** الرقم، الشركة، حالة منتهي-مصادر، اسم الباقة السابقة إن توفر، تاريخ البداية السابقة، تاريخ الانتهاء. لا إجراء تنشيط. نص التوضيح وبقية الإجراءات [فجوة]: غير معتمدة ولا تُخترع.

## 7. الشاشة الثانية: الأرقام

### الهدف والهيكل
عرض الأرقام المرتبطة بحساب العميل وإتاحة البحث والتصفية وفتح التفاصيل.
1. عنوان «الأرقام».
2. صف أدوات: حقل بحث، أيقونة تصفية الشركة، أيقونة تصفية حالة الحماية.
3. قائمة بطاقات الأرقام.
4. حالات التحميل/الفراغ/الخطأ.
5. شريط التنقل.

### بطاقة الرقم
تعرض بحسب المتاح:
- الرقم المحلي كاملًا مع بادئة الشركة.
- اسم الشركة.
- حالة الحماية: محمي/غير نشط/منتهي-مصادر.
- المدة المتبقية إذا كانت الحماية سارية (محمي).
- تاريخ الانتهاء إذا كانت غير نشطة أو مصادَرة.
- مؤشر حالة بصري ونصي.
البطاقة ملخص؛ الضغط عليها يفتح نافذة التفاصيل. لا تعرض بيانات عميل آخر أو نقاطًا أو بيانات غير متاحة.

### البحث والتصفية
- البحث ضمن أرقام العميل فقط.
- مسح البحث يعيد القائمة.
- تصفية الشركة تعرض الشركات الموجودة في بيانات المشروع فقط.
- تصفية الحالة: الكل/محمي/غير نشط/منتهي-مصادر.
- «قيد المراجعة» ليست حالة حماية ولا تظهر ضمن مرشح حالة الحماية. و«غير مشترك» لا تظهر لأن الرقم لا يدخل القائمة قبل الاشتراك.
- تظهر رسالة «لا توجد نتائج مطابقة» عند فراغ النتائج.

### تفاصيل الرقم من شاشة الأرقام — خمسة نماذج كاملة
تستخدم النافذة نفسها المستخدمة في الرئيسية، وبنية ثابتة، مع بيانات تتغير بحسب الحالة. (النموذج «غير مشترك» لا يظهر من شاشة الأرقام لأن الرقم غير مرتبط بالحساب؛ يظهر من البحث في الرئيسية فقط.)

**أ. غير مشترك** (من الرئيسية فقط)
- الرقم المحلي كاملًا.
- شركة الاتصالات.
- الحالة: غير مشترك.
- توضيح أن الرقم غير مشمول حاليًا بحماية.
- الإجراء: اشتراك.

**ب. مشترك (نشط) لدى العميل نفسه**
- الرقم المحلي كاملًا.
- شركة الاتصالات.
- حالة الحماية: محمي.
- اسم باقة الحماية.
- مدة الحماية الإجمالية.
- تاريخ بداية الحماية.
- تاريخ انتهاء الحماية.
- المدة المتبقية.
- الإجراءان: تمديد الاشتراك، والتنبيهات.

**ج. محمي لدى عميل آخر**
- الرقم المحلي كاملًا.
- شركة الاتصالات.
- حالة الحماية: محمي.
- الرسالة الحرفية: «هذا الرقم محمي حاليًا لدى عميل آخر».
- توضيح أن الاشتراك غير متاح حاليًا من هذا الحساب.
- الإجراء الوحيد: تقديم بلاغ.
- لا اسم للعميل الآخر ولا معلومات حسابه أو باقته أو مدة حمايته أو معاملاته.

**د. اشتراك منتهي (غير نشط) لدى العميل نفسه**
- الرقم المحلي كاملًا.
- شركة الاتصالات.
- حالة الحماية: غير نشط.
- اسم الباقة السابقة إذا توفر.
- تاريخ بداية الحماية السابقة.
- تاريخ انتهاء الحماية.
- آخر يوم للتنشيط إذا توفر.
- توضيح أن الحماية السابقة انتهت ولم تعد سارية.
- الإجراءان: تنشيط، والتنبيهات.

**هـ. مصادَر لدى العميل نفسه**
- الرقم المحلي كاملًا.
- شركة الاتصالات.
- حالة الحماية: منتهي-مصادر.
- اسم الباقة السابقة إذا توفر.
- تاريخ بداية الحماية السابقة.
- تاريخ انتهاء الحماية.
- لا إجراء تنشيط. نص التوضيح وبقية الإجراءات [فجوة]: غير معتمدة ولا تُخترع.

### الفرق بين السياقين
بيانات تفاصيل الرقم متطابقة للحالة نفسها سواء فتحت من الرئيسية أو الأرقام. الفرق هو سياق الدخول والإجراءات المسموح بها. لا تضف زر «الأرقام» داخل نافذة مفتوحة من شاشة الأرقام لأن العميل موجود فيها بالفعل. البحث من الرئيسية لا يضيف الرقم تلقائيًا إلى قائمة العميل.

## 8. الشاشة الثالثة: العمليات

### الهيكل
- عنوان «العمليات».
- حقل بحث.
- مرشح نوع العملية: الكل/اشتراك/تمديد الاشتراك/تنشيط.
- مرشح حالة الطلب: الكل/قيد المراجعة/معتمد/مرفوض.
- بطاقات الطلبات.
- حالات التحميل والفراغ والخطأ.
- شريط التنقل.

### بطاقة الطلب
تعرض نوع العملية، الرقم، الشركة، الباقة، تاريخ تقديم الطلب، المبلغ، وحالة الطلب.

### نافذة تفاصيل العملية
عند الضغط على بطاقة تعرض:
- نوع العملية.
- الرقم والشركة.
- اسم الباقة ومدتها.
- السعر.
- وسيلة الدفع.
- مرجع الدفع.
- تاريخ تقديم الطلب.
- حالة الطلب.
- سبب الرفض إذا كان متاحًا وكان الطلب مرفوضًا.

هذه شاشة متابعة فقط. لا تضف أزرار اشتراك/تمديد/تنشيط داخل سجل العملية. لا تخلط حالة الطلب بحالة الحماية، ولا تخترع حالات طلب أخرى.

## 9. الشاشة الرابعة: الحماية

### طبيعة الشاشة
شاشة عملية وليست تبويبًا. لا تظهر في شريط التنقل السفلي. تفتح من إجراء مناسب في تفاصيل الرقم، وتتلقى الرقم والشركة ونوع العملية وسياق الرجوع تلقائيًا. لا يختار العميل نوع العملية يدويًا.

### ترتيب المحتوى
1. عنوان «الحماية».
2. بطاقة الرقم والشركة.
3. نوع العملية الممرر: اشتراك/تمديد الاشتراك/تنشيط.
4. اختيار باقة الحماية.
5. تفاصيل الباقة المختارة.
6. اختيار وسيلة الدفع.
7. تعليمات وسيلة الدفع المختارة.
8. حقل مرجع الدفع.
9. زر «مراجعة العملية».

### الباقة
- تعرض الباقات المتاحة للشركة ونوع العملية المحددين.
- تعرض الاسم والمدة والسعر بالريال اليمني.
- لا تخترع سعرًا أو مدة أو باقة.
- إذا لم تتوفر قيم حقيقية في مصدر المشروع، استخدم بيانات تجريبية موسومة بوضوح بأنها غير معتمدة.
- المبلغ غير قابل للتحرير من العميل.

### الدفع ومرجع الدفع
- اعرض وسائل الدفع الموجودة في بيانات المشروع فقط.
- بعد اختيار الوسيلة اعرض تعليماتها الخاصة بها.
- مرجع الدفع حقل مطلوب إذا كان مطلوبًا في نموذج العملية.
- تحقق من عدم الفراغ ومن الصيغة إذا كانت معروفة.
- إدخال المرجع ليس إثباتًا لاعتماد الدفع.

### مراجعة العملية
بعد اكتمال الاختيارات والحقول، افتح نافذة تعرض:
- نوع العملية.
- الرقم والشركة.
- الباقة والمدة.
- السعر.
- وسيلة الدفع.
- مرجع الدفع.
- الإجمالي.
والإجراءات: «تأكيد إرسال الطلب» و«رجوع للتعديل». لا تضف رسومًا غير معتمدة.

### نتيجة الإرسال
بعد نجاح الإرسال فقط اعرض:
- تأكيد إرسال الطلب.
- رقم الطلب إن توفر.
- الحالة «قيد المراجعة».
- توضيح أن الحماية لا تصبح سارية بمجرد الإرسال، وأنها تنتظر الاعتماد.
- إجراء للانتقال إلى العمليات، وإجراء للعودة للسياق السابق.

عند الفشل لا تعرض نجاحًا؛ اعرض خطأ مفهومًا وإعادة محاولة، ولا تكرر الطلب تلقائيًا.

### قيد القرض/السلفة
أي احتمال قرض/سلفة من شركة اتصالات يخص الاشتراك الأول فقط، ولا يطبق على تمديد الاشتراك أو التنشيط. لا تضف مسارًا أو وعدًا بالقرض دون قرار صريح وتفاصيل معتمدة.

## 10. الشاشة الخامسة: الحساب

تعرض:
- عنوان «الحساب».
- بيانات الحساب المتاحة فعليًا.
- تصنيف الحساب: مستخدم/عميل وفق قاعدة أول اشتراك معتمد.
- إعدادات الأمان المتاحة فعليًا.
- المساعدة والدعم.
- الشروط والأحكام.
- سياسة الخصوصية.
- التواصل.
- تسجيل الخروج.

لا تخترع حقولًا قابلة للتعديل. لا تعرض نقاطًا أو محفظة أو رصيدًا أو تبويب اشتراكات. لا تعرض أدوات الإدارة أو تبديل الدور. تسجيل الخروج يفتح نافذة تأكيد أولًا.

## 11. الشاشة السادسة: الإشعارات

- عنوان «الإشعارات».
- قائمة مرتبة من الأحدث إلى الأقدم.
- كل عنصر: عنوان مختصر، نص، تاريخ/وقت إن توفر، حالة مقروء/غير مقروء.
- تمييز غير المقروء بالنص والشكل، لا اللون وحده.
- فتح الإشعار يعلّمه مقروءًا إذا كان ذلك مدعومًا.
- حالات تحميل وفراغ وخطأ وإعادة محاولة.
- لا تعرض مهام المدير أو محتوى إداريًا.
- لا تخترع أنواع إشعارات.

## 12. الشاشة السابعة: تنبيهات الرقم

تُفتح من تفاصيل رقم يخص العميل، وليست تبويبًا مستقلًا. تعرض:
- عنوان «تنبيهات الرقم».
- الرقم المحلي.
- الشركة.
- حالة الحماية.
- التنبيهات المرتبطة بهذا الرقم فقط.
- تاريخ/وقت التنبيه وحالة القراءة إذا توفرا.

لا تعرض تنبيهات أرقام أخرى أو بيانات عميل آخر. لا تخترع رادارًا أو قنوات أو دورية إرسال أو أنواع تنبيهات. عند عدم وجود تنبيهات اعرض حالة فارغة واضحة.

## 13. الشاشة الثامنة: تقديم بلاغ

تُفتح من نموذج رقم «محمي لدى عميل آخر». تعرض:
- عنوان «تقديم بلاغ».
- الرقم للعرض فقط.
- الشركة للعرض فقط.
- أسباب البلاغ:
  1. الرقم يخصني.
  2. الرقم مرتبط بحساب سابق فقدت الوصول إليه.
  3. تم تفعيل حماية رقمي دون علمي.
  4. سبب آخر.
- عند اختيار «سبب آخر» يظهر حقل توضيح نصي.
- زر «إرسال البلاغ».

يجب اختيار سبب، ويجب إدخال التوضيح عند «سبب آخر». بعد الإرسال الناجح اعرض تأكيد الإرسال دون اختراع حالة متابعة أو مدة معالجة. البلاغ لا ينقل ملكية الرقم ولا يلغي حماية العميل الآخر.

## 14. مواصفات مشتركة لنوافذ تفاصيل الرقم

النماذج الخمسة هي نافذة واحدة بتصميم ثابت:
1. مقبض سحب عند استخدام Bottom Sheet.
2. عنوان «تفاصيل الرقم».
3. زر إغلاق.
4. الرقم المحلي كاملًا.
5. اسم الشركة.
6. شارة الحالة: حالة الحماية (محمي/غير نشط/منتهي-مصادر)، وللرقم غير المشترك «غير مشترك» لأنه لا حالة حماية له.
7. تفاصيل الحالة.
8. الإجراءات المناسبة.
9. مساحة آمنة أسفل النافذة.

قواعد البيانات:
- اعرض البيانات الموثوقة المتاحة فقط.
- لا تعرض حقولًا فارغة أو أصفارًا أو شرطات توحي بوجود بيانات.
- لا تخترع تاريخًا أو مدة أو باقة.
- احذف صف المعلومة الاختيارية إذا لم تتوفر.
- لا تكشف بيانات عميل آخر.
- يجب أن تتطابق بيانات النافذة من الرئيسية والأرقام للحالة نفسها.

مصفوفة الإجراءات:
| حالة اشتراك الرقم | الرئيسية بعد البحث | شاشة الأرقام |
|---|---|---|
| غير مشترك | اشتراك | (لا يظهر في الأرقام) |
| مشترك (نشط) لدى العميل نفسه | تمديد الاشتراك + التنبيهات إذا كانت معتمدة | تمديد الاشتراك + التنبيهات |
| محمي لدى عميل آخر | تقديم بلاغ | (لا يظهر في الأرقام) |
| اشتراك منتهي (غير نشط) لدى العميل نفسه | تنشيط + التنبيهات إذا كانت معتمدة | تنشيط + التنبيهات |
| مصادَر لدى العميل نفسه | لا تنشيط (بقية الإجراءات [فجوة]) | لا تنشيط (بقية الإجراءات [فجوة]) |

لا تضف زر «الأرقام» داخل نافذة شاشة الأرقام. إذا كان من المفيد في سياق الرئيسية إظهار انتقال إلى قائمة الأرقام، فيكون إجراءً ثانويًا ولا يحل محل الإجراء الأساسي.

## 15. النوافذ الأخرى

### تفاصيل العملية
نافذة قابلة للتمرير عند الحاجة، تعرض جميع بيانات الطلب المحددة في قسم العمليات، مع عنوان وإغلاق واضحين.

### مراجعة العملية
تعرض جميع بيانات العملية قبل الإرسال، بما فيها السعر والمرجع. الإجراءات: تأكيد الإرسال أو الرجوع للتعديل.

### نتيجة الإرسال
تظهر بعد معرفة النتيجة فقط: نجاح مع رقم الطلب إن توفر وحالة قيد المراجعة، أو فشل مع سبب مفهوم وإعادة محاولة. لا تعرض نجاحًا وهميًا.

### تأكيد تسجيل الخروج
عنوان «تسجيل الخروج»، سؤال تأكيد مختصر، زرا «تأكيد تسجيل الخروج» و«إلغاء». لا تسجل الخروج عند فتح النافذة.

### نوافذ التصفية والاختيار
قائمة أو نافذة صغيرة مناسبة لعدد الخيارات، تظهر الاختيار الحالي، وتوفر إغلاقًا أو تطبيقًا حسب طبيعة المرشح. لا تستخدم نافذة ضخمة لخيارات قليلة.

## 16. حالات الواجهة العامة

كل شاشة تعتمد على بيانات يجب أن تعالج الحالات المناسبة:
- **تحميل:** مؤشر مفهوم، منع التكرار، وعدم عرض بيانات قديمة كأنها جديدة.
- **فارغة:** عنوان يوضح عدم وجود بيانات، وصف مختصر، وإجراء مناسب فقط إذا كان له معنى.
- **خطأ:** رسالة مفهومة وزر إعادة المحاولة عند الحاجة، دون Stack Trace.
- **انقطاع اتصال:** توضيح تعذر الاتصال وعدم ادعاء تنفيذ العملية.
- **انتهاء الجلسة:** تنبيه واضح والعودة إلى تسجيل الدخول دون كشف بيانات.
- **نجاح:** رسالة مرتبطة بالفعل الذي اكتمل فعلًا، مع تحديث الحالة الصحيحة.

لا تمسح مدخلات العميل عند الخطأ دون سبب. لا تترك المستخدم أمام شاشة بيضاء أو حالة غير مفسرة.

## 17. مواصفات العناصر الدقيقة

### الأزرار
- إجراء أساسي واحد واضح لكل منطقة.
- زر ثانوي أقل بروزًا.
- تعطيل الزر يوضح السبب عند الحاجة.
- أثناء التنفيذ يظهر تحميل ويمنع الضغط المتكرر.
- استخدم تسمية فعلية دقيقة مثل «إرسال البلاغ» بدل «إرسال».

### حقول الإدخال
- Label واضح مستقل عن Placeholder.
- نص مساعد عند الحاجة.
- حالة تركيز وخطأ واضحة.
- الاحتفاظ بالقيمة بعد خطأ التحقق.
- لوحة مفاتيح مناسبة لنوع الحقل.
- عدم تغطية لوحة المفاتيح لآخر حقل أو زر أساسي.

### الأيقونات والشارات
- الأيقونة موحدة ولها معنى واضح.
- لا تستخدم أيقونة مبهمة دون تسمية.
- شارة الحماية تعرض محمي/غير نشط/منتهي-مصادر.
- شارة الطلب تعرض قيد المراجعة/معتمد/مرفوض.
- لا تستخدم اللون وحده للدلالة.

### البطاقات والنوافذ
- منطقة الضغط واضحة.
- الضغط على زر داخل بطاقة لا يفعّل ضغط البطاقة أيضًا.
- البطاقة ملخص والنافذة تفاصيل.
- النوافذ السفلية بعرض مناسب وارتفاع متكيف وقابلة للتمرير.
- زر الإغلاق ظاهر.
- لا تقطع آخر عنصر أو زر بسبب حدود الشاشة أو لوحة المفاتيح.

## 18. الخصوصية والأمان
1. لا تعرض اسم العميل الآخر أو رقم حسابه أو أي بيانات تعريفية.
2. لا تعرض باقة العميل الآخر أو مدتها أو تواريخ حمايته أو معاملاته.
3. البلاغ لا يكشف معلومات الطرف الآخر.
4. لا تعرض بيانات تقنية لمجرد أنها موجودة في استجابة النظام.
5. لا تضع مفاتيح Supabase أو رموز جلسات أو أسرارًا في الواجهة أو HTML.
6. بيانات المعاينة الاصطناعية موسومة بوضوح بأنها تجريبية.
7. لا تخلط بيانات عميلين في جلسة واحدة.

## 19. متطلبات معاينة HTML المستقلة عند طلبها
- ملف HTML مستقل، يفضل أن يحتوي CSS وJavaScript داخليًا.
- يعمل محليًا بفتح الملف دون خادم أو build.
- لا يحتاج إنترنت ولا CDN ولا خطوطًا خارجية.
- لا يتصل بـ Supabase أو API أو أي خدمة خارجية.
- لا يحتوي مفاتيح أو أسرارًا.
- لا يقرأ أو يكتب في المستودع ولا يعدّل ملفاته.
- بيانات المعاينة التجريبية منفصلة وموسومة.
- التفاعلات الأساسية تعمل فعليًا: التنقل، البحث التجريبي، النماذج الخمسة، الفلاتر، اختيار الباقة والدفع، التحقق، المراجعة، نتيجة الإرسال، البلاغ، الإشعارات، تأكيد الخروج.
- لا تحاكِ اعتماد المدير كأنه اعتماد حقيقي.
- RTL صحيح في كل الشاشات والحقول والنوافذ.
- التسليم ملف قابل للتنزيل من المحادثة.

- [ ] فتح التطبيق على الرئيسية.
- [ ] ظهور الشريط العلوي والشعار والإشعارات والحساب.
- [ ] إدخال رقم محلي صحيح.
- [ ] رفض الصيغة غير الصحيحة برسالة واضحة.
- [ ] ظهور التحميل أثناء البحث.
- [ ] فتح نموذج التفاصيل الصحيح.

### تطابق نافذة التفاصيل

- [ ] مشترك (نشط) لدى العميل: الباقة والمدة والبداية والنهاية والمتبقي وتمديد الاشتراك والتنبيهات.
- [ ] محمي لدى آخر: الرسالة والبلاغ فقط، دون بيانات خاصة.
- [ ] اشتراك منتهي (غير نشط) لدى العميل: بيانات الحماية السابقة والتنشيط والتنبيهات.
- [ ] مصادَر لدى العميل: بيانات الحماية السابقة دون إجراء تنشيط.
- [ ] عدم ظهور حقول فارغة أو بيانات مختلقة.

### الأرقام
- [ ] القائمة تعرض أرقام العميل فقط.
- [ ] البحث والتصفية حسب الشركة والحالة يعملان.
- [ ] فتح البطاقة يفتح النموذج الصحيح.
- [ ] الإجراءات تتغير وفق الحالة والسياق.
- [ ] لا يظهر إجراء «الأرقام» داخل نافذة شاشة الأرقام.

### العمليات
- [ ] البحث ومرشح نوع العملية ومرشح حالة الطلب يعملون.
- [ ] بطاقة الطلب تعرض النوع والرقم والشركة والباقة والتاريخ والمبلغ والحالة.
- [ ] تفاصيل العملية تعرض كل البيانات المتاحة.
- [ ] لا يحدث خلط بين حالة الطلب وحالة الحماية.

### الحماية
- [ ] الشاشة ليست تبويبًا.
- [ ] الرقم ونوع العملية يمران تلقائيًا.
- [ ] الباقات مرتبطة بالشركة ونوع العملية.
- [ ] السعر والمدة واضحان وغير قابلين للتحرير.
- [ ] وسيلة الدفع تعرض تعليماتها الصحيحة.
- [ ] مرجع الدفع يتحقق.
- [ ] المراجعة تعرض جميع التفاصيل.
- [ ] الإرسال لا يجعل الحماية سارية.
- [ ] النجاح يظهر بعد نجاح الإرسال فقط، مع قيد المراجعة.
- [ ] الفشل لا يعرض نجاحًا ولا يكرر الطلب تلقائيًا.
- [ ] بعد نجاح تنشيط يعتمده المدير يعود الرقم محميًا، والعملية المتاحة التالية «تمديد الاشتراك».

### بقية الشاشات
- [ ] الحساب لا يعرض نقاطًا أو محفظة أو تبويب اشتراكات.
- [ ] تصنيف الحساب مستخدم/عميل يتبع قاعدة أول اشتراك معتمد، ويبقى «عميلًا» بعد انتهاء اشتراكات كل أرقامه.
- [ ] الإشعارات تعرض حالات القراءة.
- [ ] تنبيهات الرقم تخص الرقم المحدد فقط.
- [ ] البلاغ يعرض الأسباب الأربعة وحقل سبب آخر عند اختياره.
- [ ] البلاغ لا ينقل ملكية الرقم ولا يلغي حماية الآخر.
- [ ] تسجيل الخروج يتطلب تأكيدًا.

### جودة التنفيذ
- [ ] RTL صحيح بالكامل.
- [ ] لا قص أو تداخل للنصوص.
- [ ] كل الأزرار تنفذ فعلًا.
- [ ] النوافذ والحقول قابلة للاستخدام على الهاتف.
- [ ] حالات التحميل والفراغ والخطأ والاتصال والجلسة ممثلة.
- [ ] لا بيانات تجريبية تظهر كأنها حقيقية.
- [ ] المدة المتبقية والتواريخ بالتقويم الميلادي الفعلي وتوقيت Asia/Aden لا توقيت الجهاز.
- [ ] ملف HTML يعمل دون اتصال ودون تعديل المستودع.

## 22. الممنوعات
ممنوع دون قرار صريح جديد:
- تبويب حماية في التنقل السفلي.
- نقاط أمان أو محفظة أو شراء نقاط.
- تبويب أو قائمة اشتراكات مستقلة.
- إضافة الرقم تلقائيًا بعد البحث.
- اختراع أسعار أو باقات أو مدد أو شركات أو بادئات.
- كشف بيانات العميل الآخر.
- اعتبار إرسال الطلب اشتراكًا أو بدءًا للحماية.
- اعتبار قيد المراجعة حالة حماية.
- إضافة حالات طلب أخرى.
- خلط تصنيف الحساب أو حالة اشتراك الرقم أو حالة الحماية أو نوع العملية أو حالة الطلب.
- استخدام «نشط» كحالة حماية أو «غير مفعل» في وصف الحماية.
- السماح بتحرير المبلغ.
- قرض/سلفة لتمديد الاشتراك أو التنشيط.
- اختراع رادار أو قنوات أو دورية تنبيهات.
- أزرار غير عاملة أو إجراءات غير مناسبة للحالة.
- السماح بالتنشيط لرقم مصادَر.
- استخدام توقيت جهاز المستخدم في الحسابات أو عرض تاريخ بمعيار الأشهر الثلاثينية.
- تعديل المستودع عند إعداد معاينة مستقلة.

## 23. مخرجات التنفيذ ومعيار الاكتمال
المطلوب:
1. الشاشات الثماني كاملة التصميم والمحتوى.
2. النماذج الخمسة لتفاصيل الرقم في سياقي الرئيسية والأرقام.
3. نافذة تفاصيل العملية.
4. نافذة مراجعة العملية.
5. نتيجة الإرسال.
6. نافذة تأكيد تسجيل الخروج.
7. جميع حالات التحميل والفراغ والخطأ والاتصال والجلسة.
8. تنقلات وتفاعلات فعلية تحمل السياق الصحيح.
9. اختبار قبول موثق لكل البنود.
10. عند طلب HTML: ملف مستقل قابل للتنزيل والتشغيل محليًا دون تعديل المستودع.

**معيار الاكتمال:** لا تُعد الواجهة مكتملة لمجرد رسم الشاشات. يجب أن تظهر المعلومات الصحيحة كاملة، وتعمل الإجراءات في مواضعها، وتحمل الانتقالات سياقها، وتُعرض الحالات والنتائج بدقة، مع احترام الهوية والخصوصية وجميع القواعد الواردة في هذا المرجع.
