# دليل الشاشات والمسارات

## حدود المرجع

المعرّفات أدناه هي الشاشات/المسارات في ملفات `apps/*.js`. الواجهة عربية RTL ومحمولة أساسًا من معاينة العميل. أزرار التأكيد تغيّر المخزن المحلي فعليًا؛ بعض الخدمات الخارجية غير موجودة عمدًا وموسومة بأنها محلية.

## تطبيق العميل

| المعرّف | الهدف والمحتوى | أهم الأفعال والمسارات | حالات الفراغ/الفشل |
|---|---|---|---|
| `auth/login` | التحقق التجريبي من الحساب | دخول ← `home`، «إنشاء حساب تجريبي» ← `auth/signup` | بريد غير معروف أو كلمة مرور خطأ؛ يظل المستخدم دون جلسة |
| `auth/signup` | إنشاء حساب تجريبي | حفظ حساب جديد ثم الرئيسية | تحقق الاسم والبريد وكلمة المرور (8+) وعدم تكرار البريد؛ الحساب غير مشترك ورصيده صفر |
| `home` | الرصيد الفعلي، عدد الأرقام والاشتراكات وطلبات الشراء المعلقة، أرقام مختصرة | بطاقة الرقم ← تفاصيله؛ إضافة رقم ← الأرقام؛ شراء نقاط ← رصيد أمان | رسالة إضافة الرقم تنبه أنه لا ينشئ اشتراكًا |
| `numbers` | كل أرقام المالك الحالي | إضافة رقم، اكتشاف الشركة، تفاصيل الرقم | رقم غير صالح/شركة غير مكتشفة/رقم مكرر/لا توجد أرقام |
| `number-detail` (نافذة) | المالك والشركة وحالة الاشتراك والانتهاء والتعرفة المحفوظة | تفعيل أو تمديد؛ إضافة/إزالة الرادار | مدة خارج مدد الشركة أو نقاط غير كافية أو رقم غير مملوك؛ لا تُحفظ تغييرات جزئية |
| `radar` | الأرقام التي عليها الرادار والاشتراك الفعال فقط | إيقاف متابعة؛ الرجوع لتفاصيل الرقم | الرادار مجاني وغير مستقل تجاريًا في المحاكي؛ لا توجد أرقام مطابقة |
| `buy` | الباقات، السعر المالي، وسيلة الدفع وتعليماتها، مرجع إثبات تجريبي، الطلبات والحالات | إنشاء طلب ← يظهر في الإدارة؛ لا رصيد حتى الاعتماد | باقة/وسيلة غير متاحة، مرجع فارغ/مكرر، الطلب مرفوض أو معلق |
| `operations` | حركات دفتر النقاط والاشتراكات وطلبات العميل | فتح تفاصيل كل عملية (المرجع/المدة/التعرفة/النقاط) | حالة عدم وجود سجل |
| `notifications` | إشعارات هذا العميل فقط | فتح إشعار يحدّث `readAt` | رسالة فراغ؛ الإشعار محلي لا يرسل خارجيًا |
| `account` | البريد ومعرّف الحساب والصفة ورصيد أمان | نسخ المعرّف؛ فتح الإعدادات والأمان والمساعدة والشروط والخصوصية؛ تسجيل الخروج المؤكد | جلسة المتصفح مؤقتة عبر `sessionStorage` |
| `settings` | نمط فاتح/داكن/حسب الجهاز وتفضيل تنبيه الإشعارات المحلي | حفظ الاختيار في المتصفح | لا يطلب صلاحية إشعارات نظام ولا يرسل إشعارًا خارجيًا |
| `security` | وصف حدود الجلسة التجريبية | تأكيد إنهاء الجلسة | لا يوجد قفل جهاز أو مصادقة إنتاجية |

## تطبيق الإدارة

### الشريط والتنقل

- الشريط العلوي: الحساب الإداري، البحث الشامل، وصافي السجل المالي (قابل للضغط).
- الشريط السفلي من اليمين إلى اليسار: **المشتركون، المهام، الرئيسية، طلبات النقاط، الاشتراكات**.
- الزر العائم على الرئيسية يفتح «المزيد». الأزرار العائمة: المشتركون ← كل العملاء؛ المهام ← كل المهام؛ طلبات النقاط ← جميع الطلبات؛ الاشتراكات ← كل الأرقام.
- الصفحات الفرعية قابلة للعودة عبر شريط التنقل، وتعرض القسم الذي تنتمي إليه نشطًا.

| المعرّف | الغرض / العناصر | الأفعال |
|---|---|---|
| `home` | أعداد من البيانات: المشتركين، الأرقام، المهام المفتوحة؛ الطلبات المعلقة؛ المهام المستحقة؛ الاشتراكات المنتهية خلال 7 أيام | كل مؤشر/قائمة يفتح المسار الموافق؛ زر عائم للمزيد |
| `subscribers` | المشتركون فقط (حسابات لها طلب نقاط معتمد)، بحث بالاسم أو البريد أو المعرّف | تفاصيل العميل؛ زر عائم «كل العملاء» |
| `all-customers` | كل الحسابات بما فيها غير المشتركة | تفاصيل العميل؛ صفة العميل واضحة |
| `tasks` | المهام المستحقة الآن؛ رقم وشركة وعميل وموعد وقيمة وخطة وحالة | تفاصيل وتنفيذ المهمة المستحقة مرة واحدة |
| `all-tasks` | جميع المهام المخططة والمنفذة | تفاصيل؛ تنفيذ المستحق فقط؛ لا يوجد إلغاء من شاشة التنفيذ |
| `points` | الطلبات المعلقة | التفاصيل ← اعتماد/رفض؛ زر «كل الطلبات» |
| `all-requests` | كل الطلبات وحالاتها | بيانات العميل والباقة ووسيلة الدفع والمرجع والتواريخ؛ اعتماد/رفض المعلق فقط |
| `subscriptions` | الاشتراكات ذات الحالة الفعالة وتاريخ نهاية مستقبلي | تفاصيل رقم/مالك/تعرفة محفوظة؛ الإدارة للعرض فقط |
| `all-numbers` | جميع الأرقام؛ يظهر بوضوح الرقم الذي بلا اشتراك | تفاصيل الرقم؛ لا يمكن للإدارة التفعيل أو التجديد |
| `finance` | مجموع الإيرادات والمصروفات والصافي والقيود ومصادرها | إضافة قيد يدوي موجب؛ لا يغير نقاط العملاء |
| `more` | الشركات، باقات النقاط، وسائل الدفع، الإشعارات، المدخلات | فتح صفحات الإدارة المعتمدة فقط |
| `companies` | بادئات وأطوال رقم وتعرفة بالنقاط ومدد وجدولة ومصروف المهمة | إضافة/تعديل والتحقق من الحقول |
| `packages` | معرّف ثابت وعدد نقاط وسعر بالريال وحالة | إضافة/تعديل؛ الطلبات السابقة تستخدم لقطة قديمة |
| `payments` | اسم ومعلومة موجزة وتعليمات الدفع وحالة | إضافة/تعديل؛ الطلبات السابقة تحفظ لقطة التعليمات |
| `admin-notices` | إعدادات أنواع الإشعارات مفصولة عن الإشعارات التي ينشئها المسؤول | تشغيل/إيقاف؛ إنشاء إشعار محلي لفئة أو مستخدم؛ متابعة القراءة |
| `content` | الشروط والخصوصية ومعلومات التواصل | تعديل النص محليًا |
| `search` | بحث شامل في العملاء والأرقام وطلبات الشراء والشركات | النتيجة تعرض نوع العنصر وبيانًا وتفتح التفاصيل |
| `account` | حساب المدير، الوضع الداكن، إعداد قفل تجريبي، تسجيل خروج | القفل محفوظ إعدادًا توضيحيًا فقط؛ إعادة ضبط بيانات الاختبار يدويًا |

### مسار شراء النقاط

1. العميل يختار باقة ووسيلة دفع، ويرى السعر والتعليمات التاريخية.
2. يدخل مرجعًا تجريبيًا؛ ينشأ `purchaseRequest` بحالة `pending` مع لقطات الباقة ووسيلة الدفع. لا تتغير معاملة النقاط ولا الرصيد.
3. الإدارة تفتح تفاصيل الطلب وتتحقق يدويًا من المرجع في هذا النموذج (لا يوجد تحقق دفع حقيقي).
4. الاعتماد يغيّر الحالة مرة واحدة، وينشئ معاملة نقاط موجبة وإيرادًا بالريال ويرفع `isSubscriber` عند أول اعتماد، ويسجل حدثًا وإشعارًا محليًا إذا الإعداد مفعّل.
5. الرفض يغيّر الحالة دون نقاط أو إيراد.
6. العميل يقرأ البيانات المشتركة بإعادة العرض أو إعادة التحميل.

### مسار تفعيل/تمديد الاشتراك

1. العميل يفتح رقمًا مملوكًا له فقط، ويختار مدة موجودة في الشركة.
2. التكلفة المعروضة محسوبة: الأيام × تعرفة النقاط اليومية الحالية. السعر المالي بالريال ليس جزءًا من العملية.
3. عند التأكيد، تُراجع الملكية والشركة والمدة والتعرفة والجدولة والرصيد، ثم تحفظ نسخة الاشتراك وخصم النقاط وسجل التدقيق وخطة المهمة ضمن حفظ واحد للمخزن المحلي.
4. نفس معرّف التأكيد لا ينفذ مرة ثانية؛ حالة «غير كافٍ» لا تترك اشتراكًا أو خصمًا جزئيًا.
5. تمديد الاشتراك يحفظ تعرفة العملية الجديدة؛ السجل السابق يحتفظ بتعرفة وخصم سابقين.

### مسار تنفيذ المهمة

1. الإدارة ترى المهمة المستحقة مع الشركة والرقم وقيمة المصروف.
2. التحقق من أنها لم تنفذ/تلغَ وأن موعدها حل.
3. تحفظ حالة التنفيذ ووقت التنفيذ وقيد مصروف بمصدر فريد مرة واحدة.
4. تنشأ المهمة التالية من وقت التنفيذ الفعلي بحسب فاصل الشركة وقيمتها المالية، بشرط أن تقع ضمن نهاية الاشتراك.
5. يمنع التنفيذ المتكرر؛ تنشأ رسالة محلية للعميل إذا كان نوع الإشعار مفعّلًا.

### مسارات بديلة وأخطاء

- JSON تالف: تظهر رسالة، ولا تستبدل البيانات تلقائيًا. زر الاستعادة يستخدم فقط عند قصد إعادة بيانات الاختبار.
- فشل `setItem`: الدالة ترمي خطأ ولا تعرض نجاحًا.
- رقم بلا بادئة: رفض؛ طول غير صحيح: رفض؛ رقم يخص مستخدمًا آخر: رفض.
- طلب غير معلق: لا يعاد اعتماده أو رفضه.
- مهمة غير مستحقة/منفذة: لا تنفذ ولا ينشأ مصروف.
- نطاق البحث فارغ/لا نتائج: تعرض الصفحة حالة واضحة.
