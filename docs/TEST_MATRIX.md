# مصفوفة الاختبارات ومعايير القبول

## 1. اختبارات آلية موجودة

تعمل عبر `npm test` أو `node --test tests/*.test.js`. تختبر حاليًا منطق المحاكي وفحوص الاتساق المرجعي. بيانات الاختبار منفصلة عن مساحة العمل الفعلية.

| المجال | السيناريو | النتيجة المقبولة |
|---|---|---|
| تهيئة | أول قراءة دون بيانات | مخزن فارغ مع إعدادات النظام فقط |
| علاقات | أرقام/اشتراكات/مهام مرتبطة بكيانات موجودة | لا علاقات مكسورة |
| الشركة | أكثر من بادئة مطابقة | اختيار أطول بادئة فعالة |
| الرقم | طول خاطئ/بادئة مجهولة/رقم مكرر | رفض بلا كتابة جزئية |
| النقاط | حساب الرصيد | مجموع الدائن ناقص المدين |
| الشراء | إنشاء طلب | حالة pending دون نقاط أو إيراد |
| الشراء | اعتماد طلب مرة واحدة | حركة نقاط وإيراد واحدان |
| الشراء | رفض الطلب | لا حركة نقاط ولا إيراد |
| اللقطة | تعديل الباقة بعد الطلب | الطلب القديم يحتفظ بالقيم التاريخية |
| الاشتراك | رصيد غير كافٍ أو مدة غير مسموحة | رفض بلا اشتراك أو خصم جزئي |
| الاشتراك | إعادة إرسال مفتاح التأكيد | لا خصم مكرر |
| المهمة | تنفيذ قبل الموعد/بعد التنفيذ | رفض دون مصروف جديد |
| المهمة | تنفيذ صحيحة | مصروف واحد وتخطيط التالي عند انطباق الشروط |
| المالية | قيد يدوي | لا يغير رصيد النقاط |
| المالية | عكس قيد بسبب إلزامي | قيد معاكس مرتبط بالأصل، دون حذف الأصل أو السماح بعكس مكرر |
| المالية | عكس قيد عكسي | رفض العملية |
| الإشعارات | قراءة إشعار | لا يمكن لعميل قراءة إشعار عميل آخر |
| التخزين | JSON تالف أو فشل الحفظ | لا استبدال صامت ولا إعلان نجاح |
| واجهة | الأزرار العائمة/الأيقونات | ثبات البنية الأساسية وعدم اعتماد مكتبة خارجية |
| حماية | تذكرني القديم | إزالة كلمة المرور من التخزين والإبقاء على البريد فقط |
| حماية البيانات | تصدير المخزن | تنزيل JSON دون مسح أو تغيير المخزن |
| الشركات | بادئة فعالة متطابقة | رفض التعارض بين شركتين فعالتين |
| التدقيق | سجل العمليات | عرض الأحداث المحلية المسجلة |
| المرجع | مفتاح التخزين/الأدوار | لا تضارب بين الملفات؛ دورا admin/customer فقط |

## 2. اختبار يدوي للقبول قبل تسليم المرجع

1. افتح `apps/customer.html` و`apps/admin.html` على الأصل نفسه.
2. أنشئ عميلًا تجريبيًا من واجهة العميل.
3. من الإدارة أضف شركة وبادئات وأطوال ومددًا وتعرفة وفاصل مهمة ومصروفًا.
4. أضف باقة نقاط ووسيلة دفع.
5. سجّل دخول العميل وأنشئ طلب شراء؛ تأكد أن الرصيد لا يتغير قبل الاعتماد.
6. اعتمد الطلب من الإدارة؛ تحقق من زيادة الرصيد وظهور الإيراد مرة واحدة.
7. أضف رقمًا صالحًا، وتأكد أن الإضافة لا تنشئ اشتراكًا ولا تخصم نقاطًا.
8. أنشئ اشتراكًا ضمن مدة الشركة مع رصيد كافٍ؛ تحقق من خصم النقاط ولقطة التعرفة وإنشاء مهمة مستقبلية إن سمحت نهاية الفترة.
9. غيّر وقت استحقاق مهمة اختبارية إلى الماضي عبر أدوات التطوير/بيانات الاختبار، ثم نفذها؛ تحقق من قيد مصروف واحد فقط.
10. أضف إيرادًا يدويًا ومصروفًا يدويًا وتأكد أن رصيد النقاط لا يتغير.
11. اختبر رفض شراء، ومرجعًا مكررًا، ورصيدًا غير كافٍ، ورقمًا مكررًا، ومدة غير مسموحة.
12. أعد تحميل التبويبين وتأكد من اتساق العرض.

لا تستخدم بيانات مالية أو شخصية حقيقية في الاختبارات المحلية.

## 3. اختبارات غير منفذة وتتطلب بيئة خارجية

- اختبارات RLS من جلسة عميل ومدير فعليين على مشروع Supabase.
- اختبار معاملات SQL المتزامنة ومنع التكرار والتراجع عند الفشل.
- اختبار ترحيل واستعادة نسخة احتياطية.
- اختبار متصفح آلي بصري على أحجام شاشة مختلفة.
- اختبار جهاز Android أصلي، Push/SMS، أو تكامل شركة اتصالات.
- اختبار اختراق ومراجعة مستقلة للصلاحيات والأسرار والاحتفاظ بالبيانات.

## 4. سياسة الإبلاغ

يذكر تقرير الاختبار تاريخ التنفيذ والأمر المستخدم والنتيجة وعدد الاختبارات وأي قيود. لا تسجل اختبارات لم تُجرَ بوصفها ناجحة.
