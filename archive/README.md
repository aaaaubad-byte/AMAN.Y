# AMAN.Y — أمان

مرجع عربي تفاعلي محلي لتجربة واجهتي **العميل** و**المدير** والتحقق من قواعد العمل قبل ربط النظام بخدمات حقيقية.

> **تنبيه مهم:** هذه معاينة محلية وليست خدمة إنتاج منشورة. لا تتصل هذه الحزمة فعليًا بـ Supabase أو بوابة دفع أو مشغل اتصالات، ولا توفر مصادقة أو صلاحيات آمنة ضد تعديل المتصفح. لا تستخدمها لمعالجة أموال أو بيانات عملاء حقيقية.

## التشغيل

1. يتطلب التشغيل Python 3، ويتطلب تشغيل الاختبارات Node.js حديثًا.
2. شغّل `./serve.sh`، أو نفّذ `python3 -m http.server 8000 --bind 127.0.0.1` من مجلد المشروع.
3. افتح `http://127.0.0.1:8000/apps/customer.html` لواجهة العميل، و`http://127.0.0.1:8000/apps/admin.html` لواجهة المدير. يجب أن تكون الواجهتان على المضيف والمنفذ نفسيهما لتشاركا المخزن المحلي.
4. عند أول فتح لواجهة الإدارة، اختر كلمة مرور محلية وأكّدها. تُخزَّن مجزأة على هذا المتصفح، ولا توجد كلمة مرور أو بيانات اعتماد افتراضية أو آلية استعادة عند نسيانها.
5. أنشئ حساب العميل من شاشة التسجيل، ثم سجّل الدخول ببيانات الحساب الذي أنشأته. لا توجد حسابات تجريبية مُعبّأة أو تُنشأ تلقائيًا.
6. كلمة مرور الإدارة المحلية ليست مصادقة إنتاجية؛ لا تستخدم المعاينة لحفظ بيانات عملاء أو أموال حقيقية.

### بيانات الاختبار

- يبدأ مخزن المنتج فارغًا من سجلات العملاء والشركات والطلبات والعمليات؛ لا يوجد مسار `?demo=1` أو زر لتحميل عينة من واجهة المنتج.
- تبقى بيانات `tests/fixture-data.js` معزولة للاختبارات الآلية فقط، ولا يستوردها كود التطبيق.

## البيانات وحمايتها

- مخزن المعاينة هو `localStorage` بالمفتاح `AMAN_SHARED_REGISTRY_V2`، ويُشارك بين الواجهتين على أصل المتصفح نفسه.
- لا يغيّر هذا المشروع المفتاح تلقائيًا ولا يمسح البيانات عند التشغيل. لا تمسح بيانات الموقع ولا تغيّر المفتاح قبل تصدير نسخة احتياطية والتحقق منها.
- من شاشة **الحساب الإداري** استخدم **تنزيل نسخة احتياطية للبيانات** لحفظ ملف JSON محلي. قد يتضمن الملف بيانات شخصية وهاش كلمة مرور الإدارة والعملاء؛ احفظه في مكان خاص ولا ترسله علنًا.
- خيار «تذكرني» في دخول العميل يحفظ البريد فقط ولا يحفظ كلمة المرور؛ دخول الإدارة لا يحفظ بيانات اعتماد.
- لا يوجد استيراد/استعادة تلقائي لملف النسخة الاحتياطية في هذه النسخة. احتفظ بالأصل ولا تجرّب على بيانات تشغيلية دون نسخة منفصلة.

## قواعد العمل الأساسية

- الدوران داخل النطاق: المدير والعميل فقط.
- تسجيل العميل لا يجعله مشتركًا؛ اعتماد أول طلب شراء نقاط هو الذي يرفع صفة المشترك.
- طلب الشراء لا يضيف نقاطًا أو إيرادًا حتى اعتماده. الرفض لا يضيف أيًا منهما.
- رصيد النقاط مشتق من دفتر النقاط. دفتر المالية مستقل عنه؛ استخدام النقاط للاشتراك لا ينشئ إيرادًا ماليًا ثانيًا.
- إضافة الرقم لا تخصم نقاطًا ولا تنشئ اشتراكًا. تُكتشف الشركة من البادئة الفعالة الأطول المطابقة ويُتحقق من طول الرقم.
- باقات شراء النقاط مستقلة عن باقات الحماية. كل باقة حماية تحدد الشركة والمدة والتكلفة بالنقاط، وتحفظ كل عملية حماية لقطة تاريخية مستقلة.
- إعدادات المهام الثمانية مرتبطة بالشركة. تبدأ أهلية التنفيذ عند `visibleAt`؛ يمكن تنفيذ المهمة مبكرًا داخل النافذة، ويُسجل المصروف عند التنفيذ المقبول مرة واحدة. إعادة الجدولة لا تعيد ضبط الدورة، ولا يوجد اتصال تشغيلي حقيقي بمشغل اتصالات.
- تصحيح قيد مالي يتم بقيد عكسي مع إبقاء القيد الأصلي وعدم عكس القيد نفسه مرتين.
- الإشعارات داخل هذه المعاينة محلية؛ إعداد «قرب انتهاء الاشتراك» لا ينشئ مجدولًا خلفيًا.

## الاختبارات

```sh
npm test
```

الاختبارات تتحقق من قواعد البيانات المحلية ومجموعة من ضمانات الواجهة والوثائق. نجاحها لا يثبت صحة SQL أو RLS أو RPC على Supabase، ولا يغني عن اختبار المتصفح الفعلي أو الهاتف.

## خريطة الملفات

- `apps/`: HTML وJavaScript وCSS لواجهتي العميل والمدير.
- `shared/`: مخزن البيانات المحلي ومكونات الواجهة المشتركة.
- لا يحتوي هذا التصدير على مجلد `originals/`؛ مرجع التنفيذ هو الملفات الموجودة في الحزمة نفسها.
- `docs/`: قواعد العمل، نموذج البيانات، تدفق المال، تتبع المتطلبات، خطة النشر وسجل النواقص.
- `docs/SUPABASE_REFERENCE.sql`: مخطط SQL مرجعي مقترح فقط، غير منشور وغير مختبر على مشروع Supabase فعلي.
- `tests/`: اختبارات آلية وبيانات اختبار معزولة؛ يستخدمها مشغّل الاختبارات فقط ولا يستوردها كود المنتج.

## قبل الإنتاج

يلزم نشر واختبار المخطط على بيئة staging منفصلة، وتدقيق RLS وRPC والصلاحيات والتزامن والتراجع، وإكمال تدفقات الحسابات والمال والإشعارات، واعتماد البادئات والتعرفات والباقات ومصروفات المهام من صاحب النظام، ثم اختبار قبول بصري وأمني على الأجهزة المستهدفة. راجع `docs/SUPABASE_DEPLOYMENT.md` و`docs/RELEASE_CHECKLIST.md` و`docs/ISSUE_REGISTER.md`.


## تحديث المعاينة — توحيد البحث والفلترة
- حقول البحث والفلترة في الواجهتين صارت وفق الهوية المرجعية الحالية: ارتفاع 48px، زوايا 12px، خلفية `#e6e8e9`، وتُحدَّث القوائم أثناء الكتابة. (القاعدة القديمة «43px / 10px» ألغيتها إعادة بناء الواجهتين؛ المرجع الحالي: `docs/ADMIN_REBUILD_REPORT.md` و`docs/CUSTOMER_REBUILD_REPORT.md`.)
- بطاقة استعلام الرقم في رئيسية العميل تحتفظ بزر «البحث» لأنه يرسل نموذجًا مستقلًا؛ أما قوائم الأرقام والرادار فتُرشَّح أثناء الكتابة دون زر.
- لم تتغير قواعد العمل أو صلاحيات الحسابات أو عمليات البيانات.
